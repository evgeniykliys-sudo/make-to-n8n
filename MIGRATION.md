# Перенос Make → n8n: соответствия и ловушки

Всё, что ниже помечено «проверено», подтверждено в этом проекте: одинаковые заявки отправлялись
в сценарий Make и в n8n, ответы сравнивались скриптом (`tests/compare.py`).

## Соответствие элементов
| Make | n8n | Комментарий |
|---|---|---|
| Webhooks → Custom webhook | Webhook (responseMode: «Using Respond to Webhook Node») | Если в Make есть Webhook response — в n8n обязательно responseMode = responseNode |
| `{{1.phone}}` | `{{ $json.body.phone }}` | У n8n данные вебхука лежат в `body` |
| Router + фильтры на ветках | IF (две ветки) или Switch (больше двух) | |
| Фильтр `exist` / `notexist` | IF: **`is not empty`** / **`is empty`** | ⚠️ НЕ `exists`. Проверено: пустая строка `""` в Make «не существует» |
| HTTP → Make a request | HTTP Request или нативный узел сервиса (Telegram и т.п.) | Токены из URL → в Credentials n8n |
| Webhook response (status, body) | Respond to Webhook (responseCode, respondWith: text) | После промежуточных узлов `$json` — уже не исходные данные: берите `$('Имя узла').item.json` |
| `trim(x)` | `String(x ?? '').trim()` | ⚠️ `.trim()` на отсутствующем поле падает, Make — нет |
| `replace(x; "/re/g"; emptystring)` | `String(x).replace(/re/g, '')` | В Make регулярка — **строка в кавычках** |
| `ifempty(x; "y")` | `x \|\| 'y'` | ⚠️ НЕ `x ?? 'y'`. Проверено: `ifempty` считает `""` пустым, а `??` — нет |
| Строковые аргументы функций | — | В Make — в кавычках: без них «Operator on end of an expression» |

## Ловушки, пойманные тестом
Наивный перенос «как буквально написано» (`exists` вместо `is not empty`, `??` вместо `||`) —
`n8n/workflow_naive.json`. Результат сравнения с Make: **5 из 7 совпали, 2 расходятся, и обе ошибки — тихие**
(n8n отвечает 200, ничего не падает):

| Кейс | Make | Наивный n8n |
|---|---|---|
| Телефон — пустая строка | 422, заявка не отправлена | **200, менеджеру ушла заявка без телефона** |
| Пустые сообщение и источник | «Сообщение: —», «Источник: сайт» | «Сообщение: », «Источник: » |

Правильный перенос (`n8n/workflow.json`) — **7 из 7**.

## Процесс переноса для заказчика
1. Клиент присылает выгрузки сценариев (Scenario → ⋯ → Export Blueprint).
2. `python inventory.py *.json` — модули, сервисы, функции, ловушки, секреты → оценка объёма и цены.
3. Сбор тестовых данных: типичные случаи + пустые/отсутствующие поля, кавычки, переносы строк.
4. Прогон этих данных через старый сценарий → эталон ответов.
5. Сборка в n8n с учётом таблицы выше, секреты — только в Credentials.
6. Прогон тех же данных через n8n, `tests/compare.py` — до полного совпадения.
7. Переключение источника (форма, CRM) на вебхук n8n, неделя параллельной работы, отключение старого.

## Подводные камни API Make (если создавать сценарии программно)
- Cloudflare перед Make блокирует стандартный User-Agent Python (ошибка 403 / 1010) — нужен свой заголовок.
- Make не говорит, что не так в blueprint, а только «N problem(s) found»; подробности приходят **письмом** на почту
  владельца аккаунта. Точные причины в этом проекте нашлись именно так.
- В HTTP-модуле актуальной версии обязательны `serializeUrl`, `useMtls`, `followAllRedirects`, хотя в старых
  публичных шаблонах их нет. Эталон формата модулей — выгрузка сценария, собранного в интерфейсе.
- Ошибка инициализации отключает сценарий; уже активный нельзя «запустить» повторно (IM306).
